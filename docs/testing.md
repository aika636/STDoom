# Проверка

## Автоматические

```
npm install --no-save jsdom            # один раз; UI-тесты под jsdom
node tests/run.mjs                     # все юнит-тесты (node + jsdom): dos/, input/, shell/
node tools/verify-assets.mjs           # размеры и хеши всех бинарных ассетов
node tools/build-bundle.mjs            # пересобрать assets/doom/doom.zip, проверить MD5
node sandbox/serve.mjs                 # стенд без таверны: http://127.0.0.1:8123/sandbox/phase0.html

# e2e в живой таверне (своя SillyTavern на временном data-root + Chromium)
npm install --no-save playwright && npx playwright install chromium
STDOOM_ST_DIR=/путь/к/SillyTavern node tests/e2e/run.mjs [smoke] [--headed]
```

Путь к таверне задаётся только переменной окружения. Скриншоты e2e пишутся в `tests/e2e/.artifacts/`
(в `.gitignore`). Первый запуск e2e собирает фронтенд таверны, это до минуты.

Чего ждать от каждого слоя:

- **node без DOM:** маппинг `e.code` → GLFW, генерация обоих конфигов (сверка с эталонами по ключам и
  значениям), сборка бандла, MD5 (сверка с `node:crypto`), ZIP-писатель, разбор WAD, математика геймпада,
  раскладка тача, взвод автосохранения.
- **jsdom:** каркас окна и кнопка в wand-меню, перехват клавиатуры и мыши с моком `CommandInterface`,
  тач и геймпад (что именно уходит в `ci`), панель настроек, проводка в `dos/session.js`, экран отказа,
  потеря и восстановление контекста WebGL (мок намеренно не бросает: настоящий контекст тоже не бросает),
  порядок элементов `InitFs`, уборка при сбое сборки сессии, сериализация `persist()`.
- **e2e:** CSP таверны не мешает, DOOM грузится и рисует кадры, клавиши не утекают в `#send_textarea`,
  Esc не закрывает окно, подтверждение закрытия, слэш-команда `/doom`.
- **Руками:** звук, плавность, ощущение от мыши, тач и геймпад на реальных устройствах.

Wasm-эмулятор под jsdom не запускается. Фоновая вкладка не рисует кадры (`requestAnimationFrame` стоит),
поэтому визуальные проверки требуют активной вкладки.

## Ручной чеклист (то, что машиной не проверяется)

- Мышь: поворот плавный, вертикаль не двигает вперёд/назад; правая кнопка стрейфит и не открывает меню.
- Alt-Tab и сворачивание вкладки не оставляют залипших клавиш; хоткеи таверны работают после клика мимо поля.
- F2/F3 переживают закрытие окна; сохранение в игре переживает выход через F10 → y, в том числе F6 и тут же
  F10 → y (проверяет `dos/autosave.js`, правила 38, 49).
- Картинка 4:3, на узком экране леттербокс не ломает попап.
- Экран отказа: `WEBGL_lose_context.loseContext()` из консоли на запущенной игре — экран появляется сразу,
  «Продолжить» возвращает картинку через `restoreContext()`, «Закрыть» закрывает окно.
- Тач на реальном устройстве: попадание по кнопкам, контролы не закрывают HUD, читаемость на светлых сценах,
  ощущение свайп-поворота (множитель `1.6 × mouseSensitivity`), двойной тап открывает дверь (шаг 45 мс),
  `safe-area-inset` на устройстве с вырезом, страница таверны не уезжает при свайпе, системные жесты не
  оставляют залипаний, два пальца в одной зоне (правила 44, 45), экран отказа нажимается пальцем (правило 48).
- Свой IWAD с коммерческим файлом: `DOOM.WAD` со своим `DOOM.EXE` и `DOOM2.WAD` в слоте `DOOM.EXE`
  запускаются; запустит ли штатный shareware `DOOM.EXE` коммерческий IWAD; подписи версий в `KNOWN_IWADS`
  совпадают с настоящими файлами (сверена только shareware); 14-мегабайтный файл не подвешивает вкладку;
  после «Убрать» возвращается shareware; чужие сейвы не роняют игру.
- Геймпад: индексы кнопок совпадают с устройством; ощущение правого стика (`DEFAULT_SENSITIVITY = 900`);
  мёртвая зона 0.15 на изношенном стике; порог курков 0.5.
